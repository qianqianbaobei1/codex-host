## 一、本地网络（Clash Verge Rev）

### 现状配置

| 项 | 值 |
|---|---|
| 内核 | `verge-mihomo`（Clash Verge Rev） |
| 模式 | `rule` + `enhanced-mode: fake-ip` |
| 三个组 | **星维**（手动 select）· **自动选择**（url-test）· **故障转移**（fallback） |

### 问题：现有调度不适合 AI 长连接

```
  自动选择 (url-test)        故障转移 (fallback)
      │                        │
      ▼                        ▼
  每 1 天按延迟选最快       每 2 小时做故障转移
      │                        │
      └──────────┬─────────────┘
                 ▼
    ⚠ 面向「网页测速」，不是面向「AI 长连接」
```

- `url-test` 会**不关心是否有正在生成的回复**，直接按延迟切节点；
- 切节点 = 换出口 IP = **正在进行的 SSE / WebSocket 长连接直接断**；
- 对 Codex / Gemini / Claude 这种跑几十秒~几分钟的 Agent Turn，**伤害最大**。

🔲 **图 2 · 问题**：一台机器正从水管里接水（AI 流式生成），有人突然把水管换成另一根（切节点），中间一头接通、一头还连着旧管道，水断在半空。隐喻：**换管子越快，掉的水越多。**

### 方案（讨论中 · 未实行）

目标：**Session-Aware Failover**（粘性优先，故障才切）

```
                 Node Pool
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
   Standby 池              当前 Active
（JP-B/SG-A/US-C）          （JP-A）
        │                       │
   后台健康探测              AI 连接粘性
        │                       │
        ▼                       ▼
   （备用）              Healthy ──► 不切
                         Failed ──► 连续失败 N 次 → 切 Standby
```

- **AI 类流量**：Sticky + Failover（粘住节点，坏了才切）
- **普通网页 / YouTube**：才按延迟 / UDP 优化

🔲 **图 3 · 方案**：一个“神经中枢”控制台（Smart Proxy），有几根专用管道分别接 AI、YouTube、网页；AI 那根是**带吸盘固定住的**（sticky），其他可以自由换向。隐喻：**该粘的粘住，该快才快。**

## 二、Codex Host 项目

### 它是什么

> 在 **Codex Desktop** 里运行 **Pi / Claude Code / OpenCode / OMP / Grok / DeepSeek / Gemini** 等多个 Harness，
> 保留 Codex 原生体验，并让它们**协作**完成同一个任务。

### 关键设计（不走 ACP 削平）

| 层 | 做法 |
|---|---|
| Desktop 侧 | CDP / Electron Inspector 增强官方 Codex 界面，不改官方包、不重做聊天壳 |
| 协议侧 | CLI Shim 透明接入官方 app-server，Codex 请求原样转发 |
| Harness 侧 | 按各自原生接口接入（Pi 走 RPC，Claude 走 Agent SDK，再投影回 Codex 输出） |
| 编排侧 | 被委派的 Harness 建独立 Native Session 与可写 Thread，委托关系单独保存 |

> 目标是**保真**，不只“能聊”。流式、工具状态、Patch、审批、提问尽量来自 Harness 自己。

🔲 **图 4 · 架构**：一个“万能遥控器”（CodexHost）同时连接多台“家电”（各大 Agent）。遥控器不重做家电，而是**直连家电原生接口**，只把信号投到大屏（Codex Desktop）上。隐喻：**一个遥控器，指挥所有电器，画面统一投影。**

### 本轮核心目标审查结论（2026-09-10）

- Agent 切换的 Host Thread 连续性已补上外部新增消息回写 Codex 的持久化步骤；它解决的是上下文连续，不代表多个 Harness 共用一个 Native Session。
- Codex 的 `thread/goal/*`、`turn/plan/updated` 等原生协议在 Codex-owned Thread 上继续由官方 App Server 处理；External Thread 的 `/goal` 是 codexhost 自己的受控循环，外部 `/plan` 仍由具体 Adapter 负责，不能标记为“原生一致”。
- Antigravity 双账号已按 Thread 绑定、独立 HOME 和 Darwin 专用钥匙串租约收口；本仓库没有真实双账号登录、切换、重启和风控行为证据，因此状态仍为候选，不能承诺“绝不掉线”。
- 本地合成测试不等于真实 Codex Desktop、OAuth、钥匙串或代理长连接验收；正式结论必须补真实宿主 Smoke Test。

## 结论一页

```
本地网络 ──► 适合网页的节点调度
              ↓ 要升级成
        适合 AI 的 Session-Aware Failover

CodexHost ──► 保真多 Harness 接入
              ↓ 已闭环
        切模型不回弹 / 权限放行 / 额度可读
```

**代码层已通过合成回归；真实 Desktop、OAuth、钥匙串和网络长连接仍需现场 Smoke Test，不能提前称为全面顺滑。**
